# AutoTrack — запись и точный повтор движений геймпада

AutoTrack записывает **ваши собственные движения стиков и нажатия кнопок** с реального
геймпада и повторяет их в виртуальный геймпад Xbox 360 — так, как это видит игра.
Репозиторий рассчитан на прокат маршрута в NBA 2K27 («The Track»), но подойдёт любому
режиму/игре, где нужно воспроизвести одну и ту же последовательность движений.

Ключевые свойства:

* **Повтор без перебоев и лагов** — вывод идёт с частотой 250 Гц по монотонному
  расписанию (`sleep` + точное докручивание), кадры не «плывут», опоздания и пропуски
  считаются и показываются;
* **Сглаживание без задержки** — маршрут известен заранее, поэтому дрожание руки
  убирается нуль-фазовым фильтром: сигнал становится ровным, но **не отстаёт** от записи;
* **Расчёт плавности стиков** — направление, амплитуда, дрожание, угловая скорость и
  ускорение, рывки, развороты, «возвраты в центр», длительность и частота нажатий,
  а также сводная оценка 0–100 со словесным вердиктом;
* **Запись первична** — маршрут пишется с вашего геймпада (окно с живой индикацией,
  метки по ходу записи, авто-остановка комбинацией кнопок), затем повторяется в игру.

---

## 1. Как это работает

```
            запись                       обработка                     повтор
  ┌──────────────────────┐   ┌───────────────────────────┐   ┌─────────────────────────┐
  │ физический геймпад   │   │ медиана 3 (выбросы)       │   │ план: интерполяция      │
  │ 250 Гц, окно, метки  │ → │ ФНЧ 14 Гц (без сдвига)    │ → │ нуль-фазовое сглаживание│
  │ клип *.atk.json      │   │ ровная сетка 120 Гц       │   │ вывод 250 Гц → XInput   │
  └──────────────────────┘   └───────────────────────────┘   └─────────────────────────┘
            │                              │                              │
            └──────────── отчёт о плавности ┴──────── сверка план/выход ───┘
```

1. **Запись** (`record`): читаем физический геймпад, сохраняем `lx, ly, rx, ry, lt, rt`
   и битовую маску кнопок. Всё приводится к единой системе: `−1…1`, `+Y = вниз`,
   инверсия Y делается **только на выводе**.
2. **Обработка** (`process`, при записи — сразу): одиночные выбросы, ФНЧ 14 Гц,
   ровная сетка времени, плавные фронты курков.
3. **Повтор** (`play`): строим план на 250 Гц (интерполяция между записанными точками,
   короткие нажатия удлиняются до видимых игре), сглаживаем весь маршрут нуль-фазовым
   фильтром и отправляем в виртуальный геймпад.
4. **Проверка** (`report`, `--telemetry`): считаем метрики по клипу и по фактическому
   выводу, сравниваем план с тем, что реально ушло в геймпад.

## 2. Требования и установка

| | |
|---|---|
| ОС | Windows 10/11 (нужен драйвер ViGEmBus) |
| Python | 3.9+ |
| Пакеты | `pygame-ce` (обязательно), `vgamepad` + **ViGEmBus** (для вывода), `numpy` (быстрее) |

```bat
:: 1) драйвер виртуального геймпада (один раз, нужны права администратора)
::    https://github.com/nefarius/ViGEmBus/releases  → ViGEmBus_Setup_x64.msi

:: 2) окружение и пакеты
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

:: 3) проверка: покажет подключённые геймпады
python autotrack.py pads
```

Альтернативные варианты установки:

```bat
pip install -e .                 :: как пакет, появится команда autotrack
pip install -e .[dev]            :: + pytest для тестов
```

Linux/macOS: запись и анализ работают, **виртуальный вывод** (XInput) — только Windows;
для тестов без игры используйте `--pad dry`.

## 3. Быстрый старт

```bat
:: меню для Windows (всё то же самое, но кнопками)
run.bat

:: 1. посмотреть, какой геймпад видит система, и проверить оси/курки
python autotrack.py pads
python autotrack.py monitor

:: 2. записать маршрут (показывает окно, пишет до вас: Ctrl+C / кнопка «стоп» / комбинация)
python autotrack.py record track1 --duration 30

:: 3. посмотреть, что получилось (плавность записи и что изменит обработка)
python autotrack.py report clips/track1.atk.json

:: 4. повторить в игру: 3 секунды на переключение окна, затем маршрут
python autotrack.py play clips/track1.atk.json --loops 3

:: 5. если хочется точных цифр о повторе — записать телеметрию и посмотреть отчёт
python autotrack.py play clips/track1.atk.json --telemetry --telemetry-out clips/tele.atk.json
python autotrack.py report clips/tele.atk.json
```

`report` по файлу телеметрии даёт те же цифры, что и отчёт во время прогона:
границы кругов сохранены внутри клипа, поэтому стык кругов не считается «рывком»,
а сама обработка для телеметрии пропускается (это уже фактический вывод, а не запись).

Что важно во время записи и повтора:

* **Игра должна быть в фокусе** во время повтора — геймпад читает сама игра, окно
  AutoTrack можно свернуть;
* **не трогайте физический геймпад во время повтора** (иначе игра получит два ввода —
  ваш и виртуальный). В идеале — отключить его на время прогона;
* остановить повтор: `q`/`Esc`, пауза: `пробел`/`p`, поставить метку: `m`
  (или `--no-hotkeys`, если не нужны горячие клавиши);
* повтор можно запускать сколько угодно раз: `--loops 0` — бесконечно с паузой
  `--loop-gap 0.15` между кругами.

## 4. Команды

```
python autotrack.py <команда> [параметры]
```

| Команда | Назначение |
|---|---|
| `pads` | список геймпадов, которые видит система |
| `monitor` | живые значения осей/кнопок (проверка знаков и курков) |
| `record [имя]` | записать маршрут |
| `play клип` | воспроизвести маршрут в виртуальный геймпад |
| `report клип` | отчёт о плавности (+ сравнение «до/после обработки») |
| `process клип` | сгладить клип и сохранить |
| `info клип` | краткая информация и метки |
| `demo` | сгенерировать демонстрационный маршрут |
| `selftest` | самопроверка таймингов и пайплайна (без игры) |

### Ключевые параметры `play`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--rate` | 250 | частота вывода в геймпад, Гц |
| `--speed` | 1.0 | множитель скорости (0.5 — медленнее в 2 раза) |
| `--loops` | 1 | кругов; `0` — бесконечно |
| `--loop-gap` | 0.15 | пауза между кругами, с |
| `--countdown` | 3.0 | отсчёт перед стартом, с |
| `--filter` | zero | `zero` (без задержки) / `off` / `polar` / `xy` («на лету», с отставанием) |
| `--smooth-hz` | 15 | срез нуль-фазового сглаживания маршрута, Гц (0 = выключить) |
| `--min-cutoff`, `--beta`, `--beta-angle` | 1.6 / 0.02 / 0.012 | настройка фильтрации «на лету» (`polar`/`xy`) |
| `--entry-ramp`, `--exit-ramp` | 120 / 120 | плавный вход и выход в нейтраль, мс |
| `--deadzone` | 0.0 | мёртвая зона стиков в плане (чистка записи) |
| `--interp` | linear | `linear`/`cubic`/`hold` |
| `--game-fps` | 60 | влияет на минимальную длительность нажатия |
| `--min-press-scale` | 1.5 | во сколько раз удлинять слишком короткие нажатия |
| `--pad` | xinput | `xinput` (боевой) / `dry` (тест) / `null` |
| `--pad-deadzone` | 0.0 | мёртвая зона на самом виртуальном геймпаде |
| `--no-invert-y` | — | не инвертировать Y (если стик в игре «наоборот») |
| `--telemetry` | выкл | записать фактический вывод и посчитать по нему плавность |
| `--priority`, `--no-mmcss`, `--cpu` | high / — / — | тонкая настройка приоритетов и ядра |
| `--coarse` | выкл | грубый таймер (без спин-ожидания), если мешает нагрузка |

Параметры обработки доступны у `play`/`process`/`record`/`report`:
`--lowpass` (14 Гц), `--resample` (120 Гц), `--no-median`, `--no-trigger-ramp`,
`--trim-idle` (0.25 с), `--no-process`, `--process`.

## 5. Метрики плавности

```
python autotrack.py report clips/track1.atk.json
```

| Показатель | Что значит |
|---|---|
| `дрожь, %` | доля полной шкалы, которую занимает высокочастотное дрожание руки |
| `ω, рад/с` | угловая скорость стика (как быстро крутится направление) |
| `α p95, рад/с²` | 95-й процентиль углового ускорения — «дёрганость» направления |
| `развор, раз/с` | смены знака вращения: пиление/шум вместо осмысленного поворота |
| `рывки, ед/с` | колебания линейной скорости хода |
| `CV` | неравномерность хода (0 — идеально ровно) |
| `угол°` | дрожание направления в градусах |
| `ход, %` | доля времени, когда стик реально двигается |
| `оценка` | сводная плавность стика 0–100 |

Сводная оценка — взвешенная (0.30 дрожание, 0.20 угловое ускорение, 0.20 рывки,
0.15 развороты, 0.15 CV), пороги «плохо»: дрожание 1.5 %, α 50 рад/с², развороты 4/с,
рывки 0.5 ед/с, CV 1.5. Порог по угловому ускорению откалиброван по ровному
вращению (эталонный круг даёт ≈25 рад/с² при 90–95 баллах).

Плавность **фактического вывода** (`--telemetry`) считается отдельно по каждому кругу
и усредняется: разрыв на стыке двух кругов — это не дрожание стика, а смена круга.
Если смотреть телеметрию как один сплошной сигнал, стык даёт ложные «рывки».

Все производные (скорость, ускорение, рывки) считаются **после нуль-фазового сглаживания
12 Гц** — иначе численное дифференцирование на 250 Гц измеряет шум квантования, а не
движение.

### Как настраивать сглаживание под себя

Маршрут известен целиком **до** старта, поэтому по умолчанию сглаживание делается
**нуль-фазовым** фильтром: он смотрит вперёд и назад, дрожание руки убирает, а вывода во
времени **не сдвигает** — реплика не «тянет» и не отстаёт от записи.

```bat
:: по умолчанию: ровно, без задержки (срез 15 Гц, флики 30+ мс проходят целиком)
python autotrack.py play clips/track1.atk.json

:: максимально плавно (сильнее гасит дрожь, самые быстрые рывки чуть сглаживаются)
python autotrack.py play clips/track1.atk.json --smooth-hz 8

:: почти как записано (только убрать мусор выше 30 Гц)
python autotrack.py play clips/track1.atk.json --smooth-hz 30

:: вовсе без правок — ровно как в клипе
python autotrack.py play clips/track1.atk.json --filter off

:: сглаживание «на лету» (есть постоянное отставание ~1/(2π·f_c))
python autotrack.py play clips/track1.atk.json --filter polar --min-cutoff 1.6 --beta 0.02

:: сгладить саму запись (оффлайн, тоже без сдвига во времени)
python autotrack.py process clips/track1.atk.json --lowpass 10 --resample 250
```

`zero` (по умолчанию) фильтрует **амплитуду и направление стика отдельно**: у центра угол
не «дёргается», а дуга поворота остаётся ровной. Порядок величин для `--smooth-hz`:
8 Гц — «мягко» (быстрые флики 30 мс слегка сглаживаются), 15 Гц — компромисс
(флики проходят целиком, дрожание выше 15 Гц гасится), 30 Гц — почти как записано.

## 6. Точность повтора: откуда берётся «без лагов»

| Механизм | Что делает |
|---|---|
| Расписание 250 Гц | кадры идут по абсолютному плану времени, а не «сколько успели»: `sleep` + точное докручивание в конце |
| Пропуск опоздавших кадров | если кадр опоздал, план не сдвигается, а лишний кадр отбрасывается (`skip_late`) — маршрут не растягивается |
| Приоритет и MMCSS | поток поднимается до `high` и регистрируется в MMCSS «Games» (можно выключить `--no-mmcss`) |
| Точный таймер | на Windows поднимается разрешение системного таймера до 1 мс |
| Отправка только при изменениях | в vgamepad `update()` вызывается лишь когда состояние изменилось (иначе 250 Гц «душат» драйвер) |
| Нуль-фазовое сглаживание | фильтр не сдвигает сигнал во времени — в отличие от фильтрации «на лету» |
| Удлинение коротких нажатий | нажатие короче кадра игры (по умолчанию 60 FPS) продлевается, чтобы игра его заметила |
| Сверка план/выход | считается максимальное и СКО расхождение между планом и фактически отправленным состоянием |

Контрольные значения (`selftest`, частота 250 Гц): джиттер расписания — единицы
микросекунд, максимальное опоздание кадра — доли миллисекунды, опоздавшие кадры — 0–2
(на загруженной системе больше — это уже про нагрузку, а не про скрипт).

## 7. Подготовка под игру (NBA 2K27, The Track)

1. Включите геймпад **до** запуска игры и проверьте знаки в `monitor`.
2. Запишите маршрут в спокойном темпе: резкие «дёргания» стика воспроизведутся точно так
   же — игра увидит то же, что и вы.
3. Запустите `play`, переключитесь в игру за время `--countdown`, не трогайте мышь и
   физический геймпад.
4. Если в игре есть отдельная настройка чувствительности стика — она применяется поверх
   маршрута, как и к живому геймпаду; для одинакового поведения контроллера оставьте её
   неизменной между записью и повтором.
5. Steam Input и «эмуляторы DualSense» лучше отключить на время — они перехватывают
   чтение геймпада, и кнопки/оси могут приходить иначе.
6. Курки: физический геймпад отдаёт «сырые» 0…1, игра сама решает про порог;
   при записи сырое значение сохраняется как есть, при повторe — выводится в XInput.

## 8. Формат клипа

Расширение `*.atk.json` (или `*.atk.json.gz`), внутри — JSON формата `autotrack.clip`
версии 1:

```json
{
  "format": "autotrack.clip",
  "version": 1,
  "meta": {
    "name": "track1", "device": "XInput/0/Gamepad",
    "created_at": "2026-09-23T11:05:34+00:00",
    "duration": 5.99167, "rate_hz": 120.048, "samples": 720
  },
  "samples": {
    "t":    [0.0, 0.00833, "..."],
    "lx":   [0, 1685, "..."],
    "ly":   ["..."], "rx": ["..."], "ry": ["..."],
    "lt":   ["..."], "rt": ["..."],
    "btns": [0, 0, 4096, "..."]
  },
  "markers": [[1.23, "поворот 1"]]
}
```

* время `t` — секунды, монотонно; оси `lx/ly/rx/ry` — целые числа `значение × 100000`
  (`−100000…100000`), курки `lt/rt` — `0…100000`; внутри программы всё хранится в
  `float`, квантование включается **только** при сохранении/загрузке. Точность
  `1/100000` выше разрешения XInput (`1/32767`), то есть игра получает запись без потерь;
* кнопки — битовая маска (`A=1, B=2, X=4, Y=8, LB=16, RB=32, LS=64, RS=128, BACK=256,
  START=512, GUIDE=1024, DU=2048, DD=4096, DL=8192, DR=16384, TOUCHPAD=32768`);
* `markers` — метки, поставленные по ходу записи (клавиша `m` или кнопка `--marker-button`);
* клип можно править руками: `samples.t` монотонна, остальные массивы — той же длины,
  что и `t`.

Готовый пример лежит в `examples/demo.atk.json` — можно проверить повтор без геймпада:

```bat
python autotrack.py play examples/demo.atk.json --pad dry --loops 2 --telemetry
```

## 9. Частые проблемы

**`pads` ничего не находит.** Проверьте кабель/Bluetooth, закройте утилиты, которые
перехватывают геймпад (Steam Input, DS4Windows, Xbox-приложения). `--device 1` — второй
геймпад в списке.

**Игра не реагирует на повтор.** Не установлен ViGEmBus, или игра не видит виртуальный
Xbox 360. Проверьте: `python autotrack.py pads` — должен появиться лишний геймпад;
в игре переключите ввод на «Xbox-контроллер». Запустите `play` без `--quiet`, чтобы
видеть счётчик кадров.

**Стики в игре двигаются в обратную сторону.** Запустите с `--no-invert-y`
(по умолчанию Y инвертируется при выводе в XInput).

**Движение дёргается, в отчёте большая «дрожь» и «развороты».** Это запись «трясущейся»
руки: понизьте срез сглаживания на повторе (`--smooth-hz 8`) или обработайте запись
(`process --lowpass 10`). Ориентир: после обработки `дрожь` < 0.5 %, `развороты` ≈ 0.
Помните, что `--smooth-hz` ниже 10 Гц начинает сглаживать и быстрые флики (30–40 мс);
для «стрелковых» маршрутов оставляйте 15–30 Гц.

**Повтор «тянет» — руль поворачивается медленнее, чем в записи.** Проверьте режим:
`--filter zero` (по умолчанию) задержки не даёт, `polar`/`xy` дают отставание
`~1/(2π·min-cutoff)` секунд — для боевого повтора их лучше не включать. Ещё вариант —
`--filter off` (ровно как в клипе) или `--smooth-hz 30`.

**Пропускаются нажатия.** Понизьте частоту вывода (`--rate 125`), увеличьте
`--min-press-scale 2`, уберите лишнюю нагрузку, проверьте `selftest`.

**`selftest` показывает опоздания/пропуски кадров.** Посмотрите на загрузку системы:
анализ, браузер, запись экрана, антивирус. Настройки по умолчанию (`--priority high`,
MMCSS) рассчитаны на обычный рабочий стол; в крайнем случае `--coarse` и `--cpu N`.

**`vgamepad` не ставится / `VIGEM_ERROR`.** Нужен драйвер ViGEmBus (ссылка в разделе 2),
права администратора при установке драйвера. Для проверки логики без игры используйте
`--pad dry`.

```bat
python -m pytest                 :: 76 тестов: метрики, фильтры, ЦОС, план, тайминги, CLI
python -m autotrack selftest     :: самопроверка на живой машине (тайминги + повтор)
printf '' | python -m autotrack play clips/track1.atk.json --pad dry --quiet   :: прогон без игры
```

Структура пакета:

```
autotrack/
  frame.py       PadState: оси, кнопки, маски, BIT/NAME-таблицы
  timing.py      точный таймер, DeadlineLoop, LoopStats (джиттер, опоздания, пропуски)
  session.py     формат клипа, Clip (запись, нарезка, метки, сохранение)
  filters.py     One Euro «на лету», нуль-фазовое сглаживание маршрута (без задержки)
  dsp.py         ФНЧ/ФВЧ/полосовой без сдвига, медиана, ресемпл (scipy или свои биквады)
  processing.py  пайплайн чистки записи (медиана, ФНЧ, сетка, фронты курков)
  plan.py        план вывода: интерполяция, тики, минимальные нажатия, рампы
  player.py      горячий цикл 250 Гц, сглаживание маршрута, телеметрия, сверка
  recorder.py    запись с физического геймпада (SDL/pygame), окно, метки
  gamepad.py     вывод: XInputPad (vgamepad), DryRunPad, NullPad
  metrics.py     метрики осей/стиков/кнопок, оценка плавности, отчёты
  cli.py         все команды и параметры
```

## 11. Дисклеймер

Инструмент повторяет **ваши собственные** действия и предназначен для одиночных режимов
и тренировки маршрута. Использование автоматизации в онлайн-режимах может нарушать
правила игры и привести к блокировке — ответственность на вас. Игра читает виртуальный
геймпад так же, как физический: никаких вмешательств в процесс игры AutoTrack не делает.
